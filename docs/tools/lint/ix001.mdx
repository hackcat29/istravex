stellar-core checks signatures, sequence numbers and fees because consensus depends on them. It doesn't check that memo text is UTF-8, and it never interprets a muxed account's ID. [What stellar-core validates](/guide/validated-fields) has the whole list. IX001 flags the two of these that Go code most often treats as safe.

## Memo text without UTF-8 validation

**Flags:** a function that reads memo text (`Memo.MustText()`, `Memo.GetText()` or the `Text` field) and never validates UTF-8 anywhere in the same function.

`MEMO_TEXT` is up to 28 bytes, and any 28 bytes are valid. Go will happily put invalid bytes in a `string`. Then one of these happens:

- PostgreSQL rejects the row (`invalid byte sequence for encoding "UTF8"`), and ingestion stalls on that ledger.
- A JSON encoder replaces the bytes with U+FFFD, and the memo the user sees isn't the memo they sent. For exchanges that route deposits by memo, that's a lost deposit.

[`base-memo-non-utf8-local-0001`](/corpus/fixtures) is a real 28-byte memo containing `FF FE`, a lone surrogate in CESU-8 form and a Latin-1 byte. Horizon exposes `memo_bytes` alongside `memo` for exactly this reason.

```go
text, ok := memo.GetText()
if ok && !utf8.ValidString(text) {
    // store the raw bytes, or reject explicitly
}
```

The rule recognises `utf8.ValidString`, `utf8.Valid`, `strings.ToValidUTF8`, and helpers named `ValidUTF8` or `SanitizeUTF8`.

## Muxed IDs converted to a lossy type

**Flags:** a conversion of a muxed account ID (`MuxedAccount.GetId()`, `MustId()`, the `Med25519.Id` field, or a variable assigned from them) to `float64`, `float32`, `int64`, `int`, `int32` or `uint32`.

A muxed ID is any `uint64`. Converting to `float64` changes every ID above 2⁵³; to `int64`, every ID above 2⁶³ turns negative. The deposit is still credited, to a different sub-account. [`cap27-muxed-max-id-local-0001`](/corpus/fixtures) carries a destination ID of 2⁶⁴ − 1 and a source ID of 2⁵³ + 1, the smallest a double can't hold.

```go
id, err := muxed.GetId()      // uint64: keep it that way
store(strconv.FormatUint(id, 10))
```
