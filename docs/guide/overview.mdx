This guide is for anyone writing code that turns Stellar ledger data into records: indexers, explorers, wallets, custody systems, analytics pipelines. It applies in any language. Where a rule can be checked mechanically in Go, [istravex-lint](/tools/lint) does it.

Every rule cites something you can check yourself: a fixture in the corpus, a lint rule, or a measured result in `corpus/results/`. Nothing here is "best practice" by assertion.

## The one idea underneath all of it

> The envelope says what a transaction **asked** for. `LedgerCloseMeta` says what **happened**. When they disagree, the metadata is right.

Most of the rules are that idea applied to a specific field.

## Does following it work?

The replay harness measures it. An indexer that reads effects from the envelope gets **all nine** indexed cases wrong. One that follows these rules gets all nine right. [stellar/wallet-backend](/pilots/wallet-backend), which follows them today, gets all eleven fixtures it indexes right, over RPC and over the data lake. Its commits from before the September fixes get them wrong in exactly the ways rules 1, 4, 5 and 6 describe.
