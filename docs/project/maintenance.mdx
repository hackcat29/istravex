## User tracking

Istravex adds no tracking anywhere. What remains is what any host sees:

| Surface | Hosted on | What's recorded |
|---|---|---|
| istravex.com | Cloudflare Workers (static assets) | No cookies or analytics scripts; Workers logs and observability are off. Cloudflare handles requests under its own policy. |
| api.istravex.com, rpc.istravex.com | One container behind nginx on a VPS | nginx request logging is off for both hosts; the API writes no request logs. Rate limiting keeps a per-IP counter in memory for one minute. nginx's error log still records failed connections, with the client address, as it does for every site on the host. |
| docs.istravex.com | Mintlify | Mintlify records page views for its dashboard, as it does for every site it hosts. Istravex adds nothing. |
| The kit (CLI tools, runners, linter, mock RPC) | Your machine | Nothing. No network calls except the ones you ask for (fetching ledgers, goldens or SDK releases). |

## On a protocol upgrade

The next one is protocol 31. Every step below is a command, and CI fails until the last one is done.

<Steps>
  <Step title="Audit the new CAPs">
    `npm run corpus:audit` against the latest stellar-protocol. New XDR-changing CAPs appear as gaps on [CAP coverage](/corpus/cap-coverage); each gets a scenario, or a note saying why not.
  </Step>
  <Step title="Re-pin stellar-core">
    Update `kit/capture/core-pin.json` with the new version, commit and per-platform binary hashes, and the CI job's apt package version.
  </Step>
  <Step title="Bump the SDKs">
    Move the JavaScript, Go, Rust, Python and Java runners to the SDK releases for the new protocol.
  </Step>
  <Step title="Regenerate and re-run">
    `npm run corpus:generate`, `node kit/goldens/fetch.mjs`, `npm run corpus:run`, `npm run pilot:wallet-backend`, `npm run pilot:stellar-etl`, and a [mainnet scan](/corpus/capturing#finding-the-transactions) for the new protocol's patterns. The goldens move with the core pin; the probe contract moves to the soroban-sdk for the new protocol. `npm run corpus:generate-check` must pass on both platforms.
  </Step>
  <Step title="Triage">
    Any check that fails on a current pin is a finding: severity, the minimal fixture, an upstream issue, an entry in `corpus/findings.json`. `kit/check-results.mjs` stays red until it's there.
  </Step>
  <Step title="Release">
    Tag a release with the results, and note any SDK or indexer behaviour that changed. Target: within two weeks of the protocol's mainnet vote.
  </Step>
</Steps>

| Channel | What goes there |
|---|---|

## Getting involved

- **Ask** in [GitHub Discussions](https://github.com/hackcat29/istravex/discussions).
- **Report a vulnerability** privately, never as an issue. See the [security policy](/project/security).
- **Report** a wrong fixture, a lint false positive, or a broken page as a [GitHub issue](https://github.com/hackcat29/istravex/issues).
- **Contribute** a fixture for an uncovered CAP. See [Contributing a fixture](/corpus/contributing).
- **Run a pilot** on your indexer and share what you find. See [Replaying into your indexer](/pilots/your-indexer).
