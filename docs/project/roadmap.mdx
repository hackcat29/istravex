Istravex is proposed to the Stellar Community Fund (SCF #46, RFP 2). The three milestones the RFP describes are built; the award would fund [six months of new work and twelve months of maintenance](#the-funded-plan).

## Milestone 1 · Corpus and reference replay <Badge color="green">Done</Badge>

| Deliverable | Where |
|---|---|
| Corpus | [137 fixtures](/corpus/overview): 95 from mainnet, 30 from testnet, 10 generated, 2 synthetic; every one of the [470 XDR cells](/corpus/cell-coverage) real traffic uses, and [45 of the 47 CAPs](/corpus/cap-coverage) with a ledger shape |
| Fixture generator | [Pinned stellar-core generator](/corpus/generating): byte-reproducible, any passphrase, run in CI on every push |
| Manifest schema | [`corpus/manifest.schema.json`](/corpus/manifest) |
| Reference adapter | [Mock RPC](/tools/mock-rpc), [data lake](/tools/data-lake) and [replay](/tools/replay); the wallet-backend adapter |

**Acceptance:** a clean checkout validates provenance and replays the same sequence offline with stable results. CI does exactly this on every push.

## Milestone 2 · Conformance and linting <Badge color="green">Done</Badge>

| Deliverable | Where |
|---|---|
| Seven SDKs in CI | [SDK runners](/tools/sdk-runners) for JavaScript, Go, Rust, Python (`stellar-sdk` and `stellar-xdr`), Java and PHP, a [sweep](/tools/sdk-runners#sweeping-real-traffic) over 310,837 real transactions, and [stellar-core goldens](/corpus/goldens) |
| Generated cases | [45,144 valid and hostile values](/tools/generated-cases) of every XDR type through every SDK, judged by the reference decoder and, for the types it reads, stellar-core |
| Per-fixture results matrix | `corpus/results/`, the [API](/api-reference/introduction), and the site |
| Go linter, three rules | [istravex-lint](/tools/lint) |

**Acceptance:** every SDK runs the shared corpus in CI; the linter flags all three rules and passes the clean reference. Both hold.

## Against the RFP's reviewer checks

The SCF RFP lists a check for each deliverable. Each one runs in CI.

| Deliverable | Reviewer check | Where it's checked |
|---|---|---|
| Corpus and generator | Entries round-trip through rs-stellar-xdr and agree with stellar-core's `--check-lcm` goldens | [SDK runners](/tools/sdk-runners) (stellar-xdr 30.0.0, every fixture; six more SDKs alongside) and [goldens](/corpus/goldens) (15,306/15,306 frames) |
| Replay harness | The reference adapter reproduces wallet-backend #729, #731 and #716 on pre-fix commits and passes on the fixed ones | [Before and after each upstream fix](/pilots/wallet-backend#before-and-after-each-upstream-fix): all three, plus 9538b3c |
| Linter | Flags seeded violations; runs clean on current wallet-backend | The [action self-test](/operations/ci) (six seeded findings) and the [pilot](/pilots/wallet-backend#lint) (one triaged latent finding, no live ones) |
| Guide | The field-by-field table agrees with the corpus manifest; reviewed by a core or platform engineer | [What stellar-core validates](/guide/validated-fields), checked by `kit/guide/fields.mjs`; review requested, not yet done |
| Conformance runner | Reproduces js-stellar-sdk #1766, #1785 and #1789 on pre-fix tags | [Earlier JavaScript releases](/tools/sdk-runners#earlier-javascript-releases): 17.2.0 and 17.2.1 fail, 17.3.0 and 17.4.0 pass |
| Findings reports | Every failure maps to a filed issue | [Findings](/project/findings), enforced by `kit/check-results.mjs`; known failures map to their upstream issues, and the four new defects found on 18 November to drafts being filed |

## The funded plan

What's above is built and isn't part of the request. The award would put the kit inside the projects it tests and keep it current: **$55,000 in XLM**, 1,180 engineering hours at a blended $45 an hour plus $1,900 of infrastructure for twelve months. Istravex Labs' two core engineers do the work: [the team](https://github.com/hackcat29/istravex/blob/main/public/proposal.md#team).

| Work | Hours | Cost |
|---|---|---|
| The kit inside the projects it tests: a conformance job offered as a pull request to each of the seven SDK repositories and the three indexers (wallet-backend, stellar-etl, Horizon), kept working as they change | 150 | $6,750 |
| Four more SDKs, for eleven: Swift (`stellar-ios-mac-sdk`), Dart (`stellar_flutter_sdk`), .NET (`dotnet-stellar-sdk`) and Kotlin, through the corpus, the generated cases and the sweep, with release matrices | 200 | $9,000 |
| A linter for TypeScript indexers: IX001–IX003 as an ESLint plugin, then IX004 (amounts through floats), IX005 (effects from operations, not metadata) and IX006 (unbounded strkey and memo decoding) in Go and TypeScript | 160 | $7,200 |
| Three more indexer pilots: SDF's token transfer processor (CAP-0067 events) and two community indexers chosen with SCF reviewers | 170 | $7,650 |
| Coverage that keeps up on its own: the weekly sweep; a fixture captured and opened as a pull request automatically for any new cell the weekly scan finds; a monthly report; CAP-0070 and CAP-0083 closed | 120 | $5,400 |
| The next protocol upgrade, end to end | 120 | $5,400 |
| Guide v2 with the new findings, the engineer review the RFP requires ([requested](https://github.com/stellar/stellar-docs/issues/3166)), a pull request to developers.stellar.org | 80 | $3,600 |
| Twelve months of maintenance: following every finding upstream to a fix (nine filed so far), triage, the pins the [weekly monitor](/operations/ci) flags, releases, quarterly reports | 180 | $8,100 |
| Infrastructure for twelve months, at cost | | $1,900 |
