## This repository

`.github/workflows/ci.yml` runs on every push and pull request. Every job must pass before `main` deploys.

| Job | What it proves |
|---|---|
| **Corpus, runners and replay** | Every fixture matches its canonical ledger; the JS, Go and Rust runners pass; four JavaScript releases fail exactly the checks their findings explain; all three SDKs round-trip stellar-core's 15,306 golden frames; replay verdicts hold; the mock RPC serves a 542 MB corpus under a 128 MB heap; the data-lake export matches the public lake; the guide's field table agrees with the corpus; the guide exports for developers.stellar.org; `src/data/corpus.json`, the docs tables and the API spec are up to date |
| **Generate on pinned stellar-core** (×3: standalone, testnet, pubnet passphrases) | Installs SDF's stellar-core 30.0.0 package. Standalone: regenerates the committed fixtures on Linux and requires the same bytes, then verifies and runs them. Testnet and pubnet: two generations must match each other, and the result verifies and passes every runner |
| **Probe contract rebuilds byte for byte** | The committed Wasm is exactly what the pinned toolchain builds from the committed source |
| **API tests and container** | The API's tests pass, including the check that every OpenAPI path is served; the image builds and answers correctly while running read-only and unprivileged |
| **istravex-lint action (self-test)** | The action passes on clean code and fails with exactly six findings on the seeded violations |
| **Upstream pilot** | wallet-backend main indexes every fixture correctly over RPC and over the data lake; each commit before an upstream fix fails and each fix passes; every lint finding is triaged |
| **Site build and e2e** | The site builds, `wrangler deploy --dry-run` accepts the Cloudflare config, and the Playwright suite passes on desktop and mobile |

## How long it takes

The jobs run in parallel, so a push is green as fast as the slowest one. Measured on GitHub's `ubuntu-24.04` runners:

| Job | Typical time |
|---|---|
| Corpus, runners and replay | about 3 minutes (the 400-ledger memory test is 25 s of it) |
| Generate (each passphrase) | about 2½ minutes |
| Upstream pilot | about 4 minutes: wallet-backend builds at main and at seven other commits |
| Everything else | under 2 minutes each |

So the whole suite fits in a pull request's review loop: about four minutes of wall-clock time. Replay alone, against your own indexer, takes seconds: the corpus is 20 fixtures and 58 ledgers.

`node kit/check-results.mjs` is the gate inside the kit jobs. It checks results by substance (every check passed, every frame exact, every verdict correct) rather than diffing result files, which record machine-specific runtime versions.

## In your repository

Two templates let you run Istravex checks in your own CI.

### Lint a Go indexer

```yaml .github/workflows/istravex.yml
name: Istravex
on: [push, pull_request]
jobs:
  lint:
    uses: hackcat29/istravex/.github/workflows/lint-indexer.yml@v1
    with:
      packages: ./...
```

### As a step in an existing job

```yaml
- uses: actions/checkout@v7
- uses: hackcat29/istravex/actions/lint@v1
  with:
    packages: ./...
    working-directory: .
```

Both run `istravex-lint` at the matching release and fail the job on any unsuppressed finding. Findings appear as annotations on the pull request.

### Replay the corpus in your tests

Start the mock RPC as a service and point your ingestion tests at it:

```yaml
- uses: actions/checkout@v7
  with:
    repository: hackcat29/istravex
    ref: v1
    path: istravex
- uses: actions/setup-node@v7
  with: { node-version: 24 }
- run: cd istravex && npm ci --omit=dev && (npm run rpc -- --network pubnet --port 8000 &)
- run: ISTRAVEX_RPC=http://127.0.0.1:8000 go test ./ingest/...
```

Or skip the setup and use `https://rpc.istravex.com/pubnet`, within its rate limits.
